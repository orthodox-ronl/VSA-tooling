    Kuiser (straat-actie)¶

    Status: contract vastgelegd. Geïmplementeerd in mvsa kuiser: Q1–Q8 (YAML-FM, @-blok, #maat, syllabify, dictionary, banners, validate-gate, normaalvorm). Q9 = bestaande --check. VSA: checklist V1–V8 + vsa kuiser actief. Body-layout: vsa format (apart; CLI actief).

    Canonieke hub voor opkuisen naar canonieke authoring-vorm per bestandstype. Geen product, geen products-meta. Straat-CLI: {straat} kuiser — zelfde idee als normalize/validate.

    Eigendom frontmatter-schema (YAML): bibliotheek vsa-frontmatter.md. Deze hub legt vast wat tooling bij kuiser mag/moet schrijven.

    Generiek¶

    Regel Inhoud
    CLI {straat} kuiser PATH… met alleen de bronextensie van die straat
    Geen spec Exit ≠ 0 + duidelijke melding: voor dit type ontbreekt nog een kuiser-specificatie (link naar deze hub)
    Na kuiser Bestand voldoet aan het formatcontract van dat type (C2), voor zover de Q*/V*/…-reeks dat eist
    Dry-run --check / --dry-run: tonen zonder schrijven (waar geïmplementeerd)
    Straat / type Contract-reeks Status
    .mvsa (mvsa kuiser) Q1–Q9 (hieronder) Q1–Q8 actief; Q9 = --check
    .vsa (vsa kuiser) V1–V8 (hieronder) V1–V8 actief
    .mscz (mscz kuiser) — geen spec → foutmelding
    .mxl (mxl kuiser) — geen spec → foutmelding
    Partituur-PDF — geen kuiser-straat; geen spec

    normalize blijft alleen spelling/pitch/kolommen (.mvsa) of layoutprofiel (.mscz/.mxl). Kuiser is breder: metadata, syllabificatie, maatcommentaar, daarna normaalvorm.

    MVSA — checklist Q*¶

    Doel: catalogus-/werkbank-.mvsa naar canonieke authoring-vorm. Volgorde van stappen is normatief (Q1 → … → Q9).

    Keuzes (besluit)¶

    Onderwerp Keuze
    Tempo-fingerprint Ontbreekt of “tool-default” → kuiser zet 131, of 181 bij soort ∈ {tropaar, kondak, stichier}. Zo herken je kuiser-tempo’s.
    Tool-default tempo Waarden die als “nog niet bewust gezet” tellen: ontbrekend; 130 (o.a. mscz mvsa / VSA-default zonder @tempo); eventueel oudere 180. Bewust ander BPM blijft staan.
    Tempo elders verzinnen Elke tool die een tempo moet verzinnen (import, kuiser, …) volgt dezelfde 131/181-regel.
    Titel-suffix (Toon N) met hoofdletter T.
    Conflict YAML ↔ @ @-blok wint; YAML-frontmatter wordt daarnaar bijgewerkt.
    Maatcommentaar Canoniek #maat N (geen spatie na #).
    Syllabificatie bij twijfel Eerst waarschuwen; woorden (mét streepjes) aan de syllable-dictionary kunnen toevoegen; netjes afbreken zodat de redacteur meteen kan wijzigen.
    Zoektekst Interpunctie en hoofdletters volgen de L-lyrics; hele woorden (geen soft-hyphens); frasering ≈ MVSA-frases/maten.
    Taal Ontbrekende taal → nl (tenzij @taal / lyrics anders aangeven).

    Q1 — YAML-frontmatter (minimaal)¶

    Schrijf of vul gedocumenteerde sleutels (catalogus: alleen gevulde sleutels; zie bibliotheek-spec). Minimaal:

    Sleutel Inhoud
    titel Herkenbare titel; anders afgeleid van bestandsnaam + (Toon N) indien toon bekend
    taal Default nl indien ontbreekt
    soort Uit FM, anders pad/bestandsnaam
    toon 1–8 indien Oktoëchos / toon-N in pad
    bron.uitgangspunt Behouden indien aanwezig; niet verzinnen
    bron.bewerking Uitvoeringsvorm-label indien afleidbaar (pad)
    zoektekst Uit L-regels (zie keuze hierboven)
    do / mode / tempo Gelijk aan @-blok ná Q2 (plat, zolang tooling dat zo leest)

    Voorkeursvolgorde top-level: bibliotheek vsa-frontmatter — voorkeursvolgorde.

    Q2 — @-blok¶

    Zorg voor (document-start, vóór eerste LSATB-systeem):

    Directive Regel
    @title "…" Verplicht na kuiser; wint van YAML titel
    @do Behouden of uit context; sync naar FM do
    @mode Behouden of default major; sync naar FM
    @tempo Volgens tempo-fingerprint (131/181); sync naar FM
    @oct Alleen behouden/schrijven als die al zinvol aanwezig is of uit bron volgt

    Geen @tempo midden in een LSATB-systeem.

    Q3 — #maat N per systeem¶

    Regel Inhoud
    Plaats Direct vóór elk LSATB-systeem (ná @sectie mag)
    Vorm #maat N — N = canonieke eerste koormaat van dat systeem (mvsa — canonieke maatnummers)
    Opruimen Verwijder andere regels die met #maat of # maat beginnen vóór dat systeem; tussen zo’n commentaar en het systeem geen @…-directives (die horen erboven)

    Q4 — Lettergreepstreepjes plaatsen¶

    Zet soft - op L volgens syllabificatie-hub (syllabificatie.md / mvsa syllabify).

    Q5 — Dictionary-consistentie¶

    Elke soft-deling moet kloppen met de syllable-dictionary van de repo. Bij conflict of onbekend woord: waarschuwing; interactief of via vlag woorden (mét streepjes) toevoegen; of afbreken zonder half geschreven bestand (of met duidelijke non-write). Geen stille verkeerde deling.

    Q6 — Schets-/importbanners (catalogus)¶

    Bij catalogus-opkuis: strip # Imported:… / schets-WAARSCHUWING-boxbanners / # WAARSCHUWING:… / emit-sectie «specifieke waarschuwingen». Vlag --werkbank: behoud die banners (werkbank-schets). #maat N en overige redactionele comments blijven staan.

    Q7 — Validatie na schrijven¶

    Na kuiser (en na succesvolle schrijf): mvsa validate zonder errors op het resultaat. Warnings (o.a. dictionary) mogen blijven. Optioneel: bibliotheek frontmatter-canoniek --check buiten deze CLI.

    Q8 — Normaalvorm (bestaande kuiser + normalize)¶

    Daarna de bestaande authoring-kuiser + align/normalize-pad:

    • eenduidige ELM-- → ~, lone ~ weg (ook na ); soft - in woorden zoals ge-neest blijft; ~ in &-melisma blijft);
    • tip «missen woordstreepjes» alleen als het woord in de syllable-dictionary staat (geen Pyphen-ruis over losse woorden);
    • maatstrepen syncen waar eenduidig;
    • canonieke kolomuitlijning inkl. &-kolommen;
    • optioneel --pitch / --octave-style zoals nu.

    Zie semantics — canonieke layout.

    Q9 — Dry-run / check¶

    --check (of --dry-run): rapporteer voorgenomen wijzigingen; geen schrijven; exit 1 als er iets zou wijzigen (huidig mvsa kuiser --check-gedrag uitbreiden).

    VSA — V* {#vsa-v}¶

    Doel: catalogus-.vsa naar canonieke authoring-vorm (metadata + zing-deling + zoektekst + validate). Geen vsa normalize. Body-layout (strofen op regels / * vs /) hoort bij vsa format — kuiser roept die niet stil aan.

    Status: contract hieronder vastgelegd; CLI actief (vsa kuiser).

    Keuzes (besluit)¶

    Onderwerp Keuze
    Playback in bron Plat in YAML: do / mode / tempo (geen MVSA-@-blok in de body)
    Tempo-fingerprint Zelfde als MVSA: ontbrekend of tool-default 130/180 → 131, of 181 bij soort ∈ {tropaar, kondak, stichier}; bewust ander BPM blijft
    Titel Uit FM; anders bestandsnaam + (Toon N) indien toon bekend
    soort / toon Strenger dan MVSA: zie bibliotheek vsa-frontmatter (verplicht waar van toepassing)
    Zoektekst Uit VSA-lyrics (hele woorden, geen soft -); frasering ≈ strofen; zie zoektekst
    Taal Ontbrekend → nl
    Syllabificatie Eerst waarschuwen; TTY: woorden toevoegen of netjes afbreken — zelfde geest als Q4/Q5
    Body-layout Niet in kuiser → vsa format
    Lege FM (catalogus) Ongedocumenteerde / lege sleutels weg (of gelijkwaardig aan bibliotheek frontmatter-canoniek); --werkbank behoudt werkbank-skelet/rommel

    V1 — YAML-frontmatter (minimaal)¶

    Schrijf of vul gedocumenteerde sleutels (catalogus: alleen gevulde sleutels). Minimaal:

    Sleutel Inhoud
    titel Herkenbare titel; anders bestandsnaam + (Toon N)
    taal Default nl
    soort Uit FM of pad/bestandsnaam; op catalogus-.vsa verplicht waar de FM-spec dat eist
    toon 1–8 indien Oktoëchos / toon-N in pad
    bron.uitgangspunt Behouden indien aanwezig; niet verzinnen
    bron.bewerking Uitvoeringsvorm-label indien afleidbaar (pad)
    do / mode Behouden of zinvol aanvullen uit bestaande bron; niet wild verzinnen
    tempo Volgens tempo-fingerprint (131/181)

    Voorkeursvolgorde: bibliotheek vsa-frontmatter.

    V2 — Zoektekst¶

    Zet of vernieuw zoektekst uit de VSA-body (hele woorden; interpunctie en hoofdletters volgen de lyrics; frasering ≈ strofen). Onderdeel van kuiser, niet optioneel weglaten.

    V3 — Lettergreepstreepjes¶

    Zet soft - volgens syllabificatie / vsa syllabify.

    V4 — Dictionary-consistentie¶

    Elke soft-deling moet kloppen met de syllable-dictionary. Bij conflict of onbekend woord: waarschuwing; op TTY toevoegen of netjes afbreken. Geen stille verkeerde deling.

    V5 — Catalogus-FM / werkbank¶

    Catalogus-opkuis: strip lege en ongedocumenteerde frontmatter-sleutels (zelfde geest als bibliotheek frontmatter-canoniek). Vlag --werkbank: behoud werkbank-skelet / bekende debug-comments. Geen import-boxbanners zoals bij MVSA tenzij die in een .vsa voorkomen — dan dezelfde strip-regel.

    V6 — (voorbehouden)¶

    Geen lichte body-canon in kuiser. Layout → vsa format. Id V6 blijft gereserveerd (niet gebruiken voor iets anders zonder hub-PR).

    V7 — Validatie na schrijven¶

    Na kuiser (en na succesvolle schrijf): vsa validate zonder errors. Warnings (o.a. dictionary) mogen blijven.

    V8 — Dry-run / check¶

    --check: geen schrijven; exit 1 als er iets zou wijzigen.

    CLI¶

    Man-pagina: vsa kuiser.

    vsa kuiser [-h] [-o OUTPUT] [--check] [--werkbank] path [path …]

    Geen --pitch / --octave-style (MVSA-only).

    Volgorde (implementatie)¶

    Praktisch: V5 (strip) → V3/V4 → V1/V2 → V7 → schrijven; V8 = --check. Normatieve checklist-volgorde blijft V1…V8 voor documentatie.

    MSCZ / MXL / PDF¶

    Geen kuiser-checklist. mscz kuiser / mxl kuiser → foutmelding. Partituur-PDF heeft geen {straat} kuiser-pad.

    Layout/playback blijft bij mscz normalize / mxl normalize.
